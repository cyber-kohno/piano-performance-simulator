# 譜面JSONとタイの入力仕様

このJSONは3D動作検証用の入力形式です。[Editorの保存対象モデル](../../docs/plan/score-domain-model/score-domain-model.md)は、音符種類・付点・タイ・休符の順序付き記譜列です。両形式の変換・アプリ間接続は未実装です。

この検証アプリの独自JSON形式です。MusicXML／MIDIのファイル読み込みや自動運指はまだ含みません。音符には左右の手と指番号が必要です。

## 秒単位の従来形式

配列を読み込みます。`time` は押下開始の秒、`duration` は離鍵開始までの秒です。`time >= 0.12`、`duration > 0`、MIDI21〜108、指1〜5、handはleft/rightです。

```json
[
  {"time":1,"duration":0.5,"midiNote":60,"hand":"right","finger":1,"voice":"melody","tie":"start"},
  {"time":1.5,"duration":0.5,"midiNote":60,"hand":"right","finger":1,"voice":"melody","tie":"stop"}
]
```

この例は1〜2秒の1音へ結合します。1.5秒には押し直しません。

## 拍単位の形式

`version:1`、`timeUnit:"beats"` のオブジェクトです。拍は四分音符を1とします。音符・休符の `duration` も拍で、秒形式とは単位が異なります。

```json
{
  "version":1,
  "timeUnit":"beats",
  "leadIn":1,
  "tempos":[{"beat":0,"bpm":120},{"beat":2,"bpm":90}],
  "notes":[
    {"beat":0,"duration":2,"midiNote":48,"hand":"left","finger":5,"voice":"bass","tie":"start"},
    {"beat":2,"duration":2,"midiNote":48,"hand":"left","finger":5,"voice":"bass","tie":"stop"},
    {"beat":0,"duration":0.8,"midiNote":60,"hand":"right","finger":1,"voice":"melody"},
    {"beat":1,"duration":0.8,"midiNote":62,"hand":"right","finger":2,"voice":"melody"}
  ],
  "rests":[
    {"beat":4,"duration":2,"hand":"left","voice":"bass"},
    {"beat":1.8,"duration":4.2,"hand":"right","voice":"melody"}
  ]
}
```

- `leadIn` は準備のための秒数。省略時1秒、0.12秒以上です。
- `tempos` は省略時120 BPM。指定時はbeat:0が必要で、同じ拍の複数指定を拒否します。拍順への並べ替えは行います。
- テンポは指定拍から次の指定まで一定。音符・タイ・休符の途中に変更があっても、開始・終了の両端を積分して秒へ変換します。連続的なテンポ曲線は対象外です。
- `notes` は空でない配列。拍形式に秒の `time` を混在させる入力を拒否します。
- `voice` は任意の空でない文字列。省略は既定の声部です。左右の同名声部は別に扱います。
- `rests` は任意。同じ手・同じ声部での音符との重複を拒否します。他声部や反対の手の保持は妨げません。音符がない区間も休みとして再生されます。明示した終端の休符は再生時間へ含めます。

## タイ・再打鍵・指替えの区別

`tie` は省略、`start`、`continue`、`stop` のいずれかです。2音ならstart→stop、3音以上ならstart→continue…→stopとします。同じ手・声部・音程の連続した音符を照合し、指番号が同じことも検証します。

タイは元の音の終了と次の開始が一致する場合にだけ結合します。浮動小数点の差は1nsまで許容し、最後の音の終了を全体の離鍵開始とします。隙間・重複・未開始・未終了・二重開始・途中の指や奏法の変更は拒否します。入力オブジェクトは変更しません。

タイを省略した隣接同音は結合しません。同じ指を休みなく再打鍵する入力は従来どおり拒否し、通常の再打鍵には10ms以上の音間が必要です。異なる声部の同じ音をタイでまとめることもありません。正規化後に同じ指や鍵盤が競合する場合は動作計画で拒否します。

鍵を押したまま別の指へ渡す場合は、受け取る音に `action:"substitute"` を明示します（[READMEの指替え例](README.md)）。指替えはタイとは別のイベントです。指替えで受け取った音の後半を同じ指のタイで延長することはできます。continue/stopにactionを付けたり指番号を変えたりすることはできません。

## 計算の入口と確認方法

`score-input.ts` の `normalizePerformance(input)` は、秒形式・拍形式のどちらも正規化します。

- `notes`: 動作計画へ渡す秒単位の音符。タイを結合済み。
- `sources`: 変換前の音符数とタイを確認するための秒単位の元音符。配列順は入力順。
- `origins`: notesと同じ順序で、それぞれの元音符がsourcesのどこにあるかを保持。
- `tempos / rests`: 秒へ変換したテンポ境界と休符。
- `tieChains / format`: タイの本数と入力の形式。

正規化だけでは幾何的な到達を確認しません。`validate(input)` は正規化後に動作の入力・接触経路を検証し、`preparePerformance(notes)` は必要な動作計画を準備します。`validate` の戻り値は音符配列なので、終端の休符を含む長さが必要なら、正規化結果の `inputLength` も参照します。画面は元の正規化結果を保持して、入力数・演奏音符数・タイ数・休符数・現在の譜面テンポ・準備時間を表示します。演奏イベントには、鍵を再打鍵しない指替えも含みます。

「17 — タイ・複数声部・休符・テンポ変化」は53音符→48演奏音符、タイ3本・休符12個。120→90→150→120 BPM、約16.15秒です。左手は保持4区間、右手は5区間。左右の声部の保持、黒鍵の指替え、テンポ変更をまたぐタイ、速いレガート、部分離鍵、最後の休符を混在させています。

速い音列では、すでに離鍵する音と後続の準備が交差する場合、両音の実際の間隔の40%ずつまで離鍵・接近を短縮します。押鍵・保持の時刻と長さは変えず、間に空中時間を確保します。

このディレクトリで実行します。

```powershell
npm test
npm run check
npm run build
npm run check:score
```

`check:score` は同じ譜面を正規化・計画し、準備後に1000回の再生時刻を評価して件数と所要時間を表示します。Windows・Node.js 24.19.0の一例は正規化約1ms、計画約449ms、1000回の評価約58ms。ブラウザー、JIT、CPUなどで変動し、性能保証ではありません。

タイ処理と拍変換によって、動作モデルの到達範囲が広がるわけではありません。現形状で届かない配置、指や左右の同一鍵の競合は引き続き理由を表示します。標準譜面のファイル変換、運指や左右の補完、ペダル、音声は別の課題です。
