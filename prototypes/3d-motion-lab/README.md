## 起動

Node.js 24系を推奨（直近の検証はWindows・24.19.0）。このディレクトリから実行します。

```powershell
npm ci
npm run dev
```

表示されたlocalhostのURLをWebGLが使えるブラウザで開きます。通常は5173番ポートです。5174番に揃える場合は `npm run dev -- --port 5174 --strictPort` を使ってください。別環境ではソースと`package-lock.json`を移し、依存パッケージと開発サーバーを再用意します。

```powershell
npm run check
npm test
npm run build
```

## 構成

- `src/score-input.ts`: 秒／拍入力、テンポ変換、声部と休符の検証、タイの結合と元音符への対応
- `src/App.svelte`: UIと再生時計
- `src/motion.ts`: 入力検証、鍵盤・指先座標、指定時刻の姿勢計算（Three.js非依存）
- `src/held-path.ts`: 保持指の制約を重ねた掌軌道、音別の接触位置、離鍵した指の別鍵への移動と経路検証
- `src/held-motion.ts`: 保持区間の各指の時間軸、共通の掌配置、個別の鍵盤深さ、独立した打鍵経路の検証
- `src/performance-plan.ts`: 左右それぞれの音階区間の抽出、基本動作への接続範囲、両手の接触時間の競合判定
- `src/fingers.ts`: 左右の指の2節モデル、親指専用の寸法・開き角、指先の順運動学
- `src/keyboard.ts`: 描画と共通の鍵盤形状、接触域、黒鍵に対する指の中心線の干渉確認
- `src/chords.ts`: 白鍵・黒鍵2〜5音に対する共通の掌位置の探索、関節角と接触位置の計画
- `src/movement.ts`: 移動の加減速・持ち上げ・手首の回転・簡易前腕の追従
- `src/scale-motion.ts`: 両手の白黒音階の掌移動、親指の準備・対向運動の近似、中指／薬指の指またぎ、黒鍵との中心線干渉確認
- `src/wrist-motion.ts`: 持ち替え時の小さな手首の傾き・上下動、接触補正、前腕の追従と到達検証
- `src/scene.ts`: Three.js描画とカメラ
- `src/data/*.json`: 再現可能な検証入力

1単位=1m、X=鍵盤の左右、Y=上、Zの負方向=奥。白鍵幅23.5mm、鍵盤移動10mmは検証用の仮寸法。表示・入力範囲は88鍵のMIDI21〜108（A0〜C8、白鍵52・黒鍵36）。左手は青、右手は肌色。左右とも指番号1〜5は親指〜小指で、左手は左右反転したモデルです。色付き球の中心が指先基準点です。

各指は2節の簡易関節。基本動作の単音では指定指を固定の関節連動パターンで曲げ、押鍵中の掌の高さを固定し、指先のX/Zのずれを手全体の微小移動で補正します。和音では共通の掌位置を候補探索し、各指の付け根の開き角と2節の角度を幾何学的に求めます。保持中だけでなく接近・離鍵中も共通の掌位置を固定します。一般的な人体IK・可動域最適化は未実装です。

白鍵和音の接触点は、長短の異なる指が届くよう、白鍵前方の安全域（Z=0.008〜0.05m）内で指別に奥行きを選びます。接触点は押鍵中固定し、鍵盤とともに上下します。計画時に押鍵経路の姿勢をサンプリングして、検証用の開き角・関節角制限に合うか調べます。黄色の接触点表示はその計画位置です。人体の到達可能性や衝突回避を保証する判定ではありません。

移動区間では手の位置と各指の姿勢を次の音／和音へ補間します。描画と動作計算で同じ指先計算を使います。

## 3〜5音の白鍵和音（2026-10-23）

「11 — 三和音・転回形・四和音・5指」は98音。両手の音階→三和音→第1・第2転回形→四和音（ド・ミ・ソ・ラ）→5指（ド・レ・ミ・ファ・ソ）→単音→音階と進みます。選択時は区間計画方式・0.5倍。保持を見る時刻は3.25／4.25／5.25／6.25／7.25秒です。音階は前後に左右2区間ずつ計画します。

共通の掌位置の探索を2〜5指へ一般化しました。以前の接触点で全指が届けばその結果を使い、届かなければ、各指の接触奥行きを白鍵前方のZ=0.008〜0.05mで1mm刻みに探します。各候補で接近の高さから押下底まで端点と中間31点を検証し、全指が届く掌位置を選びます。関節の許容範囲は従来どおりです。接触点の補助表示は片手5個へ増やしました。

音数だけで受理する仕組みではありません。たとえばド・ミ・ソ・シの広い四和音は、現在の簡易モデルでは届かず拒否されます。人間が弾けるすべての配置を保証する判定ではなく、探索範囲と簡易形状の制約があります。この従来和音方式は同時押鍵・同時離鍵が条件です。部分離鍵や保持付き旋律は下記の保持区間として別に計画します。黒鍵混在は下記の方式に対応しています。

## 黒鍵を含む和音（2026-10-23）

「12 — 白黒混在和音・黒鍵5音」は108音。両手の白鍵音階→ハ短調の三和音→変ニ長調の三和音→混在四和音→混在5指→黒鍵5音→白鍵和音→黒鍵単音→白鍵音階と進みます。選択時は0.5倍。3.25／4.25／5.25／6.25／7.25秒で各和音を確認できます。

鍵盤形状を `keyboard.ts` へまとめ、描画と計画で同じ寸法・高さを使います。黒鍵の接触奥行きはZ=-0.071〜-0.010m。黒鍵を含む和音では白鍵もZ=-0.070〜0.050mの奥側まで使い、掌を奥へ移動して全指の位置を探します。白鍵だけの和音は従来の前方接触を維持します。指の関節制限は広げていません。配置計算の前に「演奏の準備中…」を表示し、完了まで再生と入力切替を止めます。

接近から押下底までを32分割し、演奏する指の2節の中心線が黒鍵の内部を通らないことを確認します。押している黒鍵の下降も反映します。非演奏指は、黒鍵を横切らない基本姿勢または曲げた待機姿勢を選び、切替時は補間します。左右と入力順で同点候補の選び方もそろえています。

この和音の干渉確認は接触中の指の中心線が対象です。指の厚み、掌、空中移動、左右の手の全面的な衝突回避は扱いません。白黒音階は下記の別の計画を使います。

## 白黒音階と3↔1／4↔1の持ち替え（2026-10-23）

「13 — 白黒音階・3↔1／4↔1の持ち替え」は102音。ト長調→和音→ヘ長調→和音→ロ長調の上行・下行を両手で演奏します。入力は250ms間隔・押鍵120msの非レガート。選択時は0.5倍、左右それぞれ3区間の音階計画を表示します。右手は6.25〜6.62秒と8〜8.37秒、左手は10.75〜11.12秒と12.5〜12.87秒で薬指↔親指の持ち替えを確認できます。

判定はシナリオ名や調名に依存しません。半音・全音で進む単音列から、通常の隣接指順と3↔1／4↔1の持ち替えを認識します。4音以上、開始間隔650ms以下、少なくとも1回の持ち替えが条件です。同音反復、5↔1、3半音以上の跳躍、対応外の指順などで区切り、到達・干渉を検証できない区間は基本動作でつなぎます。

黒鍵または4↔1を含む区間は、共通の掌の高さ・奥行き・親指側の寄せ方と、音ごとの接触奥行きを探索します。上行・下行の途中で掌が逆行しないよう準備位置を調整します。接触中は掌の基準位置を固定し、通常は音間の前後30%を離鍵／接近に使い、中央40%で掌を5次補間して運びます。手首連動はこの基準位置へ小さな補正を加えます。既存の白鍵3↔1方式の、押鍵中も掌を進める軌道は維持しています。

白鍵・黒鍵ごとの接触域と高さを使い、加減速打鍵の接近／離鍵の指上げは白鍵18mm以上・黒鍵6mm以上（どちらも白鍵面から18mm以上）を確保します。非演奏指は高めに曲げて待機し、次の準備へつなぐ途中も待機姿勢側へ持ち上げます。区間が全面適用される範囲では全5指の中心線と黒鍵内部の交差、非演奏指の高さを最大3ms間隔と各境界で確認します。基本動作への出入りの補間、指の厚み、掌、手同士の全面的な衝突回避は未対応です。

打鍵・非演奏指・手首の比較を切り替えても、入力時刻と各音の接触点を保ちます。手首の動作量も干渉を確認して選び、13では標準量の0.25を使います。`preparePerformance(notes)` で手首の到達検証まで読み込み時に準備し、「演奏の準備中…」が終わってから再生できます。音間ゼロの5指レガートや、同じ手で保持しながら別音を弾く奏法は、下記の保持方式に対応しています。

## 保持音・5指レガート・部分離鍵（2026-10-23）

「14 — 保持音・5指レガート・部分離鍵」は両手62音。保持音付き旋律→5指レガート→白黒和音の部分離鍵→保持中の再打鍵→従来の音階へ進みます。選択時0.5倍、保持区間は左右各4区間、後続音階は左右各1区間です。1.83秒では保持した2音と半押下中の次の音、4.65秒では指から指へのレガート、8.23秒では白黒和音の1指だけが離鍵し、11.1秒では保持音を残した再打鍵を確認できます。

同じ手の音が重なる、音間が10ms未満で異なる指へ移る、同時刻の和音に離鍵差がある場合は、音符から連結した保持区間を作ります。区間内の各指に接近・押鍵・保持・離鍵の時間軸を持たせ、共通の掌位置から接触点へ幾何計算します。保持指の角度と接触は、他の指の打鍵に影響されません。鍵盤と接触マーカーも各音の深さへ一致させ、画面の押下率を各音別に表示します。

掌位置と接触奥行きは和音の幾何探索を再利用し、区間中は固定します。各指は最大120msの接近／離鍵、60msの加減速押下を使います。60ms未満の音は部分押下で折り返します。同じ指・鍵盤の再打鍵は音間10ms以上を必要とし、その音間の半分ずつまで離鍵／接近を縮めます。音符のtime/durationを変更したり、隣接する同音を暗黙にタイへ結合したりしません。全5指と黒鍵の中心線交差を最大3ms間隔と各打鍵境界で検証し、黒鍵ごとの独立した下降量も反映します。

対応範囲は、区間全体の接触が1つの掌位置から届き、各指が区間内で同じ鍵盤を担当できる場合です。5指の順次進行、保持付き三和音内の旋律、和音の部分離鍵、同じ指の同じ鍵への再打鍵を扱います。これは固定保持方式の範囲です。保持しながらの掌移動と離鍵後の別鍵移動は下記の追加方式へ拡張しました。同一鍵への明示した指替えと対応するレガートの持ち替えは下記の追加方式へ拡張しました。届かない配置は引き続き拒否します。全接触を同時に満たす保守的な計画なので、人間が弾ける範囲より狭くなります。

保持区間はすべての移動比較方式で同じ独立した加減速打鍵を使います。音階用の3つの比較チェックは保持区間へ適用しません。手首は固定し、前腕は掌へ追従します。heldPlansFor(notes)で保持区間を参照でき、HandFrame.depthsがactiveNotes／targetsと同じ順序で各音の深さを返します。keyDepth(frame,midiNote)が描画用の鍵盤深さを返します。基本動作との空中移動、指の厚み・掌・手同士の全面的な干渉、人体速度上限は未保証です。

## 保持しながらの掌移動・離鍵した指の別鍵移動（2026-10-23）

「15 — 保持しながら掌移動・指の別鍵移動」は両手60音。中指を保持した親指のド→レ→ド、黒鍵の親指移動、小指のソ→シ→ラ、固定保持の部分離鍵、従来の音階と進みます。左手は右手の鍵盤配置を鏡映した別音域です。選択時0.5倍。保持は左右各4区間、うち掌移動各3区間、音階各1区間。2.2秒は白鍵、6.3秒は黒鍵、10.5秒は小指の別鍵移動を確認できます。例では掌が約16〜20mm移動します。

入力の音符と指番号から計画します。固定保持で扱える区間はその方式を維持し、同じ指が区間内で別鍵を弾く場合や、全体が1つの掌位置から届かない場合に追加の軌道を探索します。音ごとの接触奥行きと、全打鍵経路へ届く掌Xの範囲を求め、各時刻で有効な指の制約を重ねます。掌Y/Zは候補から選んで区間内は一定、掌Xは前後の節点との移動を減らすよう調整し、接触窓の境界間を5次補間します。接触点はその音の接近〜離鍵中に固定し、幾何解で保持指を合わせ続けます。

別鍵へ移る同じ指には音間10ms以上を必要とし、離鍵／接近をそれぞれ音間の30%までに制限して空中移動を残します。同じ鍵の再打鍵は従来の50:50を維持します。自由な指は前後の関節姿勢をつなぎ、曲げた待機姿勢側へ持ち上げます。全指の到達、黒鍵に対する中心線干渉、非接触指の高さを最大3ms間隔と接触・補間の境界で検証します。音符のtime/duration、音別の鍵盤深さ、保持中の指先の世界位置を保ち、再生とシークは同じ計画を評価します。

区間が終わった掌位置と各指姿勢から、次の基本動作や音階へ接続します。HeldPlan.pathのtimes／positions／targetsが節点の時刻・掌位置・eventsと同じ順序の音別接触点を持ちます。画面では保持区間のうち掌が動く区間数を表示し、動作中は「保持を保って掌を移動」と表示します。保持中の手首は固定で、音階用の比較チェックはこの方式へ適用しません。

この初期の掌移動方式は接触中の指順が交差しない配置を対象にします。レガートの持ち替えと明示した指替えは下記に対応しました。タイは後続です。探索は有限で、全入力の受理や曲全体の最適化、人体速度、厚みのある指・掌・手同士の全面的な干渉は保証しません。前後の基本動作との空中移動の全面的な干渉も未保証です。

## レガートの持ち替え・押したままの指替え（2026-10-23）

「16 — レガートの持ち替え・押したままの指替え」は両手88音。白鍵の3↔1往復、白鍵の4↔1往復、黒鍵を含む3↔1往復、白鍵と黒鍵の3→4の指替え、通常の同音反復、従来の音階と進みます。音階部分以外の持ち替えは400ms間隔・保持480msで80ms重なります。選択時0.5倍。保持は左右各5区間（持ち替え各3・指替え各2）、後続音階各1区間です。2.23／2.63秒の3↔1、6.63／7.03秒の4↔1、11.23秒の黒鍵を含む持ち替え、14.7〜15.32秒と17.7〜18.32秒の指替えを確認できます。

持ち替えは入力の半音・全音と指番号から認識し、650ms以下の開始間隔の3↔1／4↔1を候補にします。親指に対向量と専用の開き角を適用し、2音が重なっても別々の鍵盤深さと固定接触点を保ちます。必要なら交差する2音の接触Xを鍵幅の内側3mmを残す範囲で寄せ、奥行き・掌位置と合わせて探索します。親指の対向量は準備・回復と次の空中移動にも補間します。人体の骨格や全面的な指同士の干渉を再現する仕組みではありません。

同じ鍵を押したまま指だけ替える場合、受け取る音に任意項目 action: "substitute" を明示します。省略時は通常の押鍵です。普通の同音反復を、暗黙に保持や指替えへ変換しません。指替えのtimeは受け取る指が接触する時刻、durationはそこからその指が離鍵を開始するまでです。元の音のtime/durationは変更しません。受け取りは元の指の押下完了後で、元の指の保持中または離鍵開始時刻に行い、受け取る指は元の指より長く保持する必要があります。保持相手がない、同じ指、音高が異なる、押下途中、保持が短すぎる入力は理由を表示して拒否します。

例（右手・白鍵）：

~~~json
[
  {"time":1,"duration":1.2,"midiNote":64,"hand":"right","finger":3},
  {"time":1.7,"duration":1,"midiNote":64,"hand":"right","finger":4,"action":"substitute"}
]
~~~

## 移動の自然さと比較

「06 — 近接・跳躍・和音切替」では、左手が低音を保持する間に右手が近接音・遠い音へ移動し、後半に両手の和音切替を確認できます。以下は「従来の加減速・持ち上げ・手首」の仕様です。現在のUI初期値は「区間ごとの動作計画（両手）」で、対応外の入力には従来の加減速方式を使います。

- 接触中は従来の処理を維持し、離鍵（通常120ms、短い音間では短縮）を終えてから移動します。
- 新方式は距離に応じた移動時間（通常300ms以上、短い音間では短縮）を、次の接近開始までの空き時間内で確保。到着時刻から逆算して出発します。空き時間が不足する大きな跳躍では短時間に移動するため、人体の速度限界の保証はありません。
- 空中移動は5次の補間で加減速。両端の速度をゼロとし、8〜65mmの持ち上げ量を距離から求めます。持ち上げ軌道自体も両端で速度ゼロになります。
- 指の姿勢は移動時間の75%までに次の音／和音の準備姿勢へ到達します。
- 手首を軸に移動中だけ最大約7度の前後・左右の傾きを与えます。接近前に姿勢を戻し、保持中の指先接触を変えません。手首の位置と回転は時刻から直接評価します。
- 「従来の直線・一定速度」と同じ再生時刻で切替可能。単音・黒鍵・和音の接近〜離鍵は同じです。比較の切替時に姿勢の差が即座に現れるのは比較用の動作です。

「前腕を表示」で肘から手首の簡易形状を切替できます。前腕長は245mm。肘は手首から身体側の仮の方向へ配置し、長さを保って追従します。上腕・肩・肘の固定・解剖学的な可動域は扱いません。主画面は全鍵と前腕を収め、拡大画面は手元を中心に表示します。

主画面は全鍵表示を維持し、その下に左右別の追従拡大表示を用意しています。拡大画面は対象の手だけを表示し、接近・押下・保持・離鍵をシークやコマ送りで確認できます。チェックボックスで非表示にできます。

`time`は押下開始時刻（秒）、`duration`は押下開始から離鍵開始まで。従来の打鍵では通常120ms前から接近し、開始後60msで鍵盤底に達します。通常の離鍵は120ms、手の移動は300ms。同じ手の音間が540msより短い場合は、離鍵・移動・接近を12:30:12の比率で音間に収まるよう短縮します。この従来方式の音間は10ms以上です。音間のない異なる指の接続や重複音は、下記の保持区間へまとめます。同じ指・鍵盤の再打鍵には10ms以上の音間が必要です。短い音間では持ち上げと手首の振れも小さくします。両手の音階区間の加減速打鍵は、下記の時間配分を使います。

鍵盤の平行移動、非対象指や手同士の干渉、接近・押鍵・離鍵での単純な補間は既知の制約です。音声・一般的な指くぐり・全面的な衝突回避は未対応です。単音の黒鍵と旧サンプルは引き続き使用できます。演奏しない側の手はホーム位置で待機します。持ち上げ軌道を使っても、鍵盤や他の指との干渉の完全回避は保証しません。

「手動で指の開閉を確認」を選ぶと演奏を停止し、左右を選んで各指の付け根の開き角をスライダーで変更できます。＋は親指側、−は小指側（左右反転）。親指は±22度、他の指は±31度の検証用範囲で、左右の値を保持しリセットできます。手動設定は観察専用で、演奏姿勢やJSONには反映しません。モードを解除するかシナリオを選ぶと演奏に戻ります。

JSONは `{ "time": 1, "duration": 0.5, "midiNote": 60, "hand": "right", "finger": 2 }` の配列。`hand`は`left`または`right`。ファイル読み込みはローカル処理で、サーバーへ送信しません。不正な入力は理由を表示し、直前の有効データを維持します。

## 目視確認の手順

1. 基本シナリオで、C4を指2、D4を指3、E4を指1が押すことを確認。
2. 一時停止・シーク・コマ送りで、色付き指先の中心と黄色の接触点が保持中に一致することを確認。
3. 白鍵と黒鍵のシナリオで高さ・奥行きの変化を確認。
4. 「88鍵の両端と中央」で最低音A0・最高音C8を押鍵し、斜め上／真上の両視点で全鍵が画面内に収まることを確認。横幅を変えると全鍵表示を再調整します。自由操作後は視点ボタンで全鍵表示に戻ります。
5. 速度変更と逆方向シークで同じ時刻の姿勢が変わらないことを確認。
6. 両手シナリオで、1〜4秒の左手の保持中に右手だけが離鍵・移動・再押鍵することを確認。拡大表示と0.25倍再生で指定指の曲げ・戻しを観察。
7. 「05 — 指の開閉・白鍵2音和音」で、1秒・2.6秒の右手2音、4.2秒の左右の2音、5.8秒の両手の親指／小指の2音を確認。保持中に各指先と黄色の接触点の中心が一致することを確認。
8. 手動開閉モードで右手と左手の親指・小指を広げ、片手の操作がもう一方に影響しないこと、リセットとモード解除が機能することを確認。
9. 同一指への2音指定、左右の同一鍵への同時接触、範囲外の入力、届かない和音、6音以上、長さ違いがエラーになることを確認。
10. 06シナリオを0.25倍再生し、右手の近接移動と跳躍（2.65〜4秒・4.45〜5.8秒）を比較。移動の比較を切替え、持ち上げ・加減速・到着前の指の準備を確認。
11. 7.6秒・9.2秒の和音保持中に比較を切替えても指先の接触・鍵盤の深さが変わらないこと、移動中に左手保持が変わらないこと、前腕表示の切替と両視点の全鍵表示を確認。
12. 07／08の音階シナリオを1倍と0.5倍で再生し、125ms間隔の押鍵、親指への持ち替え、上行・下行、両手の同期を確認。
13. 09を選び、音階方式・0.25倍になることを確認。親指の事前準備・中指への持ち替え・指先と接触点を右手拡大で確認。同じ時刻で従来の加減速方式へ切り替え、手全体の往復の差を比較。
14. 07の上行・下行で掌が進行方向へ動くこと、08の左手でも指くぐり・指またぎが使われること、05／06では従来方式が使われることを確認。
15. 音階方式の「非演奏指を次の音へつなぐ」を同じ時刻でオン／オフし、押鍵中の指や掌は変わらず、非演奏指の戻りと待機姿勢が変わることを確認。09の1.25秒をシーク・コマ送りでも比較。
16. 09／07で「打鍵に加減速をつける」を切り替え、押鍵開始・離鍵開始の時刻は共通であること、途中の鍵盤深さ・離鍵の時間・指上げが変わることを確認。非演奏指の比較も独立して切り替え、08の左手にも加減速が適用され、05の和音は基本動作であることを確認。
17. 09の1.39秒／1.515秒、07の1.39秒／2.515秒で「手首・前腕を持ち替えに連動」を切り替え、指先と接触点・鍵盤深さは共通で、手首の傾きと前腕の向きが変わることを確認。0.25倍再生と逆方向シーク、前腕表示の切替も確認。

18. 10を0.5倍で終端まで再生。1〜2.9秒の両手音階、3.25秒の和音、3.85秒の黒鍵、4.30秒の跳躍先、5〜6.9秒の別音域の音階を確認します。左手2区間・右手2区間と表示され、前後の音階で持ち替え動作に戻ること、シークや比較切替で接触が崩れないことを確認します。
