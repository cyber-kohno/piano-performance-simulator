# MCP譜面構築API

更新日：2026-11-10（日本時間）

> 継続編集APIへ拡張した。現在のツール・操作・revision・制約は[継続的な譜面編集](./score-editing-api.md)を優先する。以下は構築MVP時点の仕様・検証記録で、同一チェックアウト限定や旧上限等を含む。

新規構築MVPの入力仕様と実装記録。目的・範囲は[設計引継ぎ](./score-authoring-mvp-handoff.md)を維持する。現在のAPIは本資料を優先する。

アプリの既存表現とMCP入力の対応範囲は[記譜表現の棚卸し](./notation-capabilities.md)を参照。装飾音符・トリル等のアプリ側既存機能は、現在の構築MCPには含まれない。

## 呼び出し

`begin_checkout → apply_edit（必要回数）→ finish_checkout`。

```json
{
  "sessionId": "GUIと照合した完全なUUID",
  "checkoutId": "begin_checkoutの戻り値",
  "requestId": "page1-system1",
  "operations": [
    {
      "type": "create_score",
      "settings": { "meter": [4, 4], "keyFifths": 0, "tempo": 100 },
      "measures": [
        { "upper": [[{ "value": "1", "pitches": ["C5", "E5"] }]] }
      ]
    }
  ]
}
```

`create_score`は初期設定とセクション1個だけで、小節も参照表現もないプロジェクトに限る。初期設定の変更やセクション名は維持し、指定された設定で初期設定を更新する。設定の省略・既定値は設けない。

`append_measures`は同じチェックアウトで`create_score`に成功した後だけ利用できる。既存曲への追加、前のチェックアウトで作った曲への再チェックアウト後の追加は対象外。追加では`settings`を指定できない。

`meter`は分子1–32、分母1・2・4・8・16・32。`keyFifths`は−7～7、`tempo`は整数10–400。既存モデルのテンポ規則に従い、複合拍子では付点四分音符を拍とする。

## 小節・声部・音符

- `upper`・`lower`はそれぞれ声部配列。1–3声部、各声部は1–256イベント。
- 配列の添字が小節間の声部の対応を表し、内部では段ごとの`voice-0`～`voice-2`を使う。声部IDは小節をまたいで共有する識別子で、譜面要素の永続IDとは異なる。
- 段全体を省略すると声部1の全小節休符になる。指定する場合は空配列・`null`を認めない。声部数は小節ごとに変更できるが、タイ継続中の声部は省略できない。
- 指定した声部は小節を過不足なく埋める。開始位置は順番と音価から導出し、不足分の休符補完はしない。
- 通常音符は`{ "value": "4", "pitches": ["C4"] }`、和音は複数音高、休符は`{ "value": "4", "rest": true }`。
- 音価は`1, 2, 4, 8, 16, 32`に0～2個の付点を付けた文字列。例：`"4."`、`"8.."`。
- 音名は大文字A–G＋任意の`bb, b, #, ##`＋オクターブ番号。中央ドはC4。調号によって指定音高が変わることはない。
- 音域はA0–C8。描画処理で同じ音名・臨時記号・オクターブへ戻せる綴りだけ受理する。例えばC調のCbb4は現モデルでは保存できず、`UNSUPPORTED_SPELLING`となる。
- 和音内の重複MIDI音高は拒否し、降順へ並べる。UI入力の和音幅制限や声部間の同音衝突制限は構築へ追加しない。
- 未対応フィールドは拒否する。部分和音タイや装飾音等の暗黙変換は行わない。

## 連符・タイ

基本連符は次の形式。`actual`は2–16、`normal`は1–16で異なる値。`base`は付点なしの音価。イベントはちょうど`actual`個で、全て`base`と同じ付点なし音価の音符・休符とする。混合音価と入れ子は対象外。

```json
{ "tuplet": { "actual": 3, "normal": 2, "base": "8", "events": [
  { "value": "8", "pitches": ["C5"] },
  { "value": "8", "rest": true },
  { "value": "8", "pitches": ["E5"] }
] } }
```

音符の`tie: true`は、同じ段・声部の直後のイベントへ和音全体を継続する。相手の全音高と綴りが一致する必要がある。休符や欠けた声部へ接続できない。連符内外の接続にも同じ規則を適用する。

分割末尾のタイはサービスの構築状態に保持し、不成立の`tieTo`を保存しない。次の追加で接続を解決する。未解決なら`finish_checkout`は`UNRESOLVED_TIES`で拒否し、作業用データと所有権を維持する。

## 適用・再送・上限

1回の`operations`全体を候補データへ適用し、全成功時だけ作業用データを更新する。失敗した要求は以前の成功要求を変更しない。最終反映時には保存形式、時間、要素ID、声部内ID重複、タイの相互参照・範囲・時刻・音高と接続予定を再検証する。

`requestId`は英数字・`_ . : -`の1–128文字。チェックアウト内で成功要求だけを記憶する。同じID・同じ操作内容は元の結果を返し、小節を追加しない。オブジェクトのキー順は無視する。配列順と値は比較する。同じID・異なる内容は`REQUEST_ID_CONFLICT`。失敗要求は修正して同じIDで再送できる。

再送記録は完了・停止時に破棄する。新しいチェックアウトへ旧要求を流用しない。タイムアウト後は元の`checkoutId`と`requestId`で同じ要求を再送し、結果を確認する。`finish_checkout`自体の再送は従来どおり終了済みIDを拒否する。

| 上限 | 値 |
| --- | --- |
| 操作数／要求 | 16 |
| 追加小節数／要求 | 合計32 |
| operationsの正規化UTF-8 JSON／要求 | 48 KiB |
| 成功構築要求数／チェックアウト | 64 |
| 構築小節数／チェックアウト | 512 |
| 内部HTTP本文／応答／WebView待ち | 従来の64 KiB／256 KiB／5秒 |

内部HTTPはエンベロープや空白を含む本文サイズにも制限があるため、要求全体は64 KiB以内に収める。これらは入力上限であり、全ての上限の組み合わせで5秒以内の処理を実測保証するものではない。`get_editor_state`は従来の全件取得のため、大きな譜面では応答上限に注意する。範囲取得は未追加。

成功結果は`changed, requestId, firstMeasure, lastMeasure, addedMeasures, addedNotes, unresolvedTies`。小節番号は1始まり、音符数は和音を1イベントとして数える。再送では元の要約を返すため、現在の累計とは限らない。

エラーは`code`と`message`。メッセージ中の`operations[0].measures[1].upper[0][2]`等は入力JSONの0始まりの位置を示す。音価の差は16分音符単位の有理数で返す。

既存の単一`operation: "set_pitch_fingering"`形式は維持する。構築要求と運指要求は別々に送り、同じ要求へ混在させない。運指形式には今回の再送記録を追加しない。

## GUI反映・確認用データ

`finish_checkout`で一度だけ実プロジェクトへ反映し、Undo履歴を1件追加する。新規構築時は最初の小節をアウトラインで選択し、タイムラインカーソルを先頭へ戻す。履歴には反映後のフォーカスも記録する。通知前のUIロック解除と強制停止時の全破棄は従来どおり。

[8小節入力例](./score-authoring-example.json)は`apply_edit`へセッション・チェックアウトIDを追加して使用できる。一括入力に加え、4小節目で分割するとタイの未解決・追加入力による解決を確認できる。後半は新しい`requestId`と`append_measures`で送る。
