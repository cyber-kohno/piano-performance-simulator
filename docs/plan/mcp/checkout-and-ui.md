## 状態と編集の反映

チェックアウト状態は「解除済み」「編集中」の2状態。通知の表示状態は所有権・ロックと独立させ、完了待ち状態は持たない。

1. `begin_checkout(sessionId)`で所有者、固有の`checkoutId`、開始時プロジェクト、作業用プロジェクト、編集カーソルを保持する。
2. UIの編集操作をロックする。入力の下書き・メニュー・ダイアログ・ファイル操作・再生がある場合は開始前に`EDITOR_BUSY`で拒否する。
3. `get_editor_state`は作業用プロジェクトと現在の編集情報を返す。`apply_edit`は作業用データだけを更新する。どちらも所有者と`checkoutId`が一致する必要がある。
4. `finish_checkout`は開始時と実プロジェクトが同一であることを確認し、蓄積した編集を一度だけ反映してUndo履歴を1件記録する。変更がなければ履歴を作らない。
5. 所有権を破棄し、UIロックを解除してから完了通知を表示する。通知をOK・Escapeのどちらで閉じても、ロック状態は変わらない。

同じ所有者による編集中の`begin_checkout`再要求は同じIDを返す。他の所有者は`CHECKOUT_BUSY`で拒否する。終了済み・停止済みのIDは、同じ所有者が新たにチェックアウトしても再利用できない。

## 強制停止

チェックアウト中の`Stop MCP editing`ボタン、またはCtrl＋Shift＋Mで作業用データと所有権を破棄し、UIロックを解除してから停止通知を出す。MCP公開停止・サービス破棄でも作業用データと所有権を解放する。

反映と停止はWebViewの同期処理で直列に実行する。停止が先なら変更は反映されず、反映が先なら全変更が反映済みとなる。完了後の取り消しは通常のUndoで行う。エージェントの応答がなくても手動停止できる。自動の切断検知やリース期限は設けていない。

## UIの排他

- 共通キー処理の先頭で強制停止を判定し、次にチェックアウト中のキー入力を抑止する。
- フロート入力は共通キー処理から文字列・カーソル状態を更新し、部品内でキーイベントを消費しない。
- UIからの変更入口は共通の`uiEditAllowed`で確認する。文字入力確定、メニュー操作、Undo/Redoの状態復元、ファイル読込の反映、再起動等の遅延コールバックにも適用する。
- エディターを`inert`にし、ポインターを受けるロック表示で覆う。入力・メニュー・設定画面はチェックアウト中に表示しない。強制停止ボタンはロック対象の外に置く。
- チェックアウト開始前に未確定入力や非同期ファイル処理を拒否し、開始・解除時は保持キーをリセットする。編集中のウィンドウ終了要求は拒否し、先に完了または強制停止してもらう。

## フロートテキスト

Scorehackの`FloatingTextInputLayer`と入力コントローラーを参考に、HTML inputを使わず文字列とカーソル位置を保持する。黒背景、白文字、Consolas等幅14px・太字、縦線カーソル、枠線・角丸・影・エラー色を合わせる。位置は対象要素の近くに表示し、画面端へ収める。

入力可能文字は`a-z A-Z 0-9`と空白・`_ ' . , # -`。左右キー、Backspace、Delete、Enter確定、Escapeキャンセルに対応する。IMEとCtrl/Meta/Altを伴う入力は処理しない。既存文字列の末尾から編集を開始する。文字数上限と運指の値検証は維持する。外側のクリックでも下書きを破棄する。

## 現段階の範囲と検証

対応編集は運指設定1種類。個別の引数・対象検証と既存のNoteEditor/EditTransactionを通す。汎用操作配列、条件検索、譜面全体の独立した整合性検証器は別段階で設計する。作業用データへの各要求は個別に検証し、拒否された要求は作業用データを変更しない。それ以前に受理した要求は維持する。

`tests/mcp-editor.test.mjs`は一括反映、停止、遅延要求、所有者、開始拒否、入力検証、実プロジェクト競合を確認する。`tests/mcp-session.test.mjs`は公開ライフサイクルと公開解除時のロック解除、`tests/floating-text-input.test.mjs`は独自入力の文字編集・キー制御を確認する。

今回の検証：関連11件成功、MCP Rustテスト4件成功（ソケット通信テストは通常のWindows権限で実行）、stdio smoke成功。型チェックはエラー0・既存警告3、フロントエンドビルドとデスクトップdebugビルド成功。ブラウザー実画面で外観・文字挿入削除・カーソル移動・確定・キャンセル・Undoを確認した。実GUIを介したチェックアウトから反映／強制停止までの通し検証は未実施。

全体テストは362件中342成功・20失敗。HEADのソースを隔離展開した比較では355件中334成功・21失敗で、失敗名の比較により新規失敗0件、旧MCP公開テストの失敗1件解消を確認した。譜面編集等の既存20件は今回の対象外。
