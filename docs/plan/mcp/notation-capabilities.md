# 記譜表現とMCP入力の対応範囲

更新日：2026-11-10。現行ソースの型、domain編集、MusicXMLプレビュー、演奏イベント生成、MCP入力検証を照合した棚卸し。継続編集APIの実GUI検証記録は下記リンク先を参照。

> 継続編集API追加後の対応表へ更新済み。入力・解除の具体的な操作と実GUI検証範囲は[継続的な譜面編集](./score-editing-api.md)を参照。

画像の判読はエージェントの責務。本資料は、読み取った記譜を現行アプリ／MCPへ渡せるかを扱う。

「アプリ側あり」は該当する保存モデル・実装があるという意味で、任意の記譜や全ての組み合わせの対応を保証しない。MCP欄は基本構築と専門編集操作を合わせた対応範囲。

| 通常音符・和音・休符・全小節休符 | あり | 対応。段省略で全小節休符 |
| 全音符～32分音符、付点・複付点 | あり | 対応 |

| オクターブ線 | ottavaEvents、専用処理あり | set_ottava_event／remove_ottava_event。段と、音符から独立した位置を指定 |

| 反復記号・括弧・D.C.／D.S.等 | 現保存モデルに専用表現なし | 非対応。小節を展開して音列を渡すことは可能 |

## 既存機能の主な制約

- 装飾音符は主音の前に置く列。GUIの追加処理は単音の主音を対象とし、主音が32分音符なら追加不可。装飾音符の和音・後置装飾音・任意の装飾記号を網羅するものではない。
- トリルは単音または同音のタイ連結が対象。補助音は調内音・半音・全音、開始は主音・補助音。任意の和音トリル等は対象外。domain・保存・MCPの打鍵回数を2–128に統一した。
- MCP連符は保存モデルの範囲へ拡張した。actualとイベント数が一致し、書かれた音価合計がactual個のbase音符と同じである必要がある。入れ子は不可。
- MCPの音高はA0–C8。音名が現在のMIDI＋綴り方向モデルで同じ綴りに戻る場合だけ受理する。全ての異名同音・重変化記号を保存できるわけではない。
- 和音の各音は同じ音価を共有する。保持長の違う音は複数声部などの構造で表す必要がある。和音内の同じMIDI音高の重複指定は不可。
- 一般的なモルデントや反復等を通常音符列へ展開できても、原譜の専用記号を保持したことにはならない。
- 既存曲へ新しいチェックアウトで追加・修正できる。音高・音価・声部置換・小節挿入削除等の専門操作を用意。全置換は音符IDを再生成するため、関係の明示解除・再設定が必要になる場合がある。

## 根拠コード

- アプリの保存モデル：code/apps/editor/src/domain/score/types.ts

アプリ側の既存記譜表現を、基本構築と28種類の専門操作から扱えるようにした。操作契約と主要保存フィールドの対応表を型チェックし、アプリとMCPの対応を維持する。上記のモデル自体にない表現は、今後アプリ・MCPを合わせて拡張する。
