### 目的とユーザーとの合意

- `apps/3d-motion-lab` は、演奏動作の方式・見た目・対応範囲を見極める検証アプリ。方向性が固まったら別プロジェクトで再設計し、長期保守用のコード・テストを整える方針。
- 検証アプリは Vite + Svelte + TypeScript + Three.js。Tauri、楽譜エディタ、自動運指、音声は今は追加しない。入力は秒単位の音符配列、または拍・テンポ・声部・休符を持つ独自JSON。
- **検証時点から88鍵すべてを主カメラ内に収める。** 手元の拡大表示は補助表示。全鍵表示を省略する代替にはしない。
- 一度に最終目標まで実装せず、映像をユーザーと確認しながら段階的に進める。最終目標は実写に近い演奏映像だが、現在は簡易形状・動作の対応確認が中心。

### 重要な制約・設計境界

- 保持区間では固定配置を維持できる場合は従来方式を使い、別鍵移動・持ち替え・指替えなどに掌Xの軌道を探索する。掌Y/Zと手首の姿勢は区間内固定。半音・全音の3↔1／4↔1を候補とし、親指の対向量と接触X/Zも探索する。すべての配置の受理は保証しない。6音以上の同時押鍵、同一指の重複、指定のない同一鍵の重複、届かない経路は拒否する。
- 同じ指への同時の2音指定、明示した指替え以外の同一鍵の重複、対応する3↔1／4↔1以外の交差運指、簡易モデルで届かない和音、左右の同一鍵への同時接触は検出して拒否。和音のエラーに左右・開始時刻・MIDIと指を含める。ド・ミ・ソ・シなど広い四和音も現モデルでは届かない場合がある。人体の演奏可能性を判定する仕組みではない。
- 従来打鍵では接近／離鍵の基準時間は各120ms、移動の基準時間は300ms。音間が540msより短ければ離鍵・移動・接近を12:30:12で短縮。白鍵3↔1方式の加減速打鍵では音間を50:50（到達範囲に収まらなければ40:60）で離鍵・接近へ配分し、各最大120ms。**従来方式の音間と同じ指・鍵盤の再打鍵には10ms以上必要。別鍵への同一指の移動は離鍵／接近を音間の各30%までに抑えて中央に空中時間を残す。異なる指のレガートは保持区間として扱う。540msは下限ではない。** 押下は60msで底に到達。60ms未満の音は、加減速打鍵では長さに応じた部分的な深さで速度ゼロにして折り返す。
- 動作は時刻から評価し、フレームの積み重ねで位置を決めない。入力検証・和音計画・描画を分ける。
- 単音では指先の弧に伴うX/Zずれを手の位置で補正する。和音では共通の掌位置を固定し、各指の角度を求める。白鍵の接触奥行きはZ=0.008〜0.05mで指別に選ぶ。以前の接触点で届かなければ1mm刻みで奥行きを探索し、接近から押下底までの経路を32分割して確認する。黒鍵を含む和音は黒鍵Z=-0.071〜-0.010m、白鍵Z=-0.070〜0.050mを使い、掌も後方まで探索する。描画と接触域の鍵盤形状はkeyboard.tsで共通化。関節制限は従来どおりで、全指の接触が可能な配置だけ受理する。
- 音階方式は左右それぞれの半音・全音の単音列、通常の隣接指順、3↔1／4↔1の持ち替えを含む区間に限定（4音以上・開始間隔650ms以下・持ち替え1回以上）。白鍵3↔1の掌Xは単調3次補間。黒鍵または4↔1では掌のY/Z・親指側の寄せ方・接触奥行きを探索し、接触中の基準位置を固定、音間の中央40%で5次補間して運ぶ。通常は前後30%を離鍵／接近へ割り当てる。親指の対向運動は付け根の前方移動と開き角の近似。手首連動は到達と黒鍵中心線の干渉を確認して動作量を選ぶ。和音・跳躍・長い休止・対応外運指で区切り、検証できた区間だけ音階動作を適用する。出入りの補間は隣の音の接触を避けた空中移動内に収め、区間同士の範囲は重ねない。曲全体の移動量や人体速度は最適化しない。
- 従来の移動方式の手首の傾きは空中移動中のみ。両手の音階区間では接触目標を手首回転の座標系へ逆変換して補正し、接触中も小さく動かす。保持中の接触点を壊す一律の平滑化は使わない。前腕は長さ245mmの追従表示で、肩・上腕・解剖学的に自然な肘は扱っていない。
- 物理演算・全面的な衝突回避・人体速度制限・音声・ペダル・動画出力は未実装。保持区間は個別の黒鍵下降を反映して全体、黒鍵を含む和音は接触中、新しい音階方式は全面適用中の待機・準備・移動も含め、指の2節の中心線と黒鍵内部の交差を確認する。厚みのある指や掌、基本動作との出入りの補間、手同士の全面的な干渉は未検証。全面的な人体IKはなく、指の2節モデルに対する幾何計算を用いる。

### 別環境での再開手順

**このMarkdownだけではアプリは再現できない。** 少なくとも `apps/3d-motion-lab` のソース・設定・`package.json`・`package-lock.json`、および `docs/plan` を同じ相対配置で移す。`node_modules` と `dist` は再生成でき、別OSのものを持ち込む必要はない。Gitのコミットやリモートへの反映は本作業で実施していないため、別環境に最新ファイルが届いていることを確認する。

1. この「現在の状態」を読む。
2. [アプリREADME](../../apps/3d-motion-lab/README.md)で詳細な仕様と目視確認手順を読む。[初期構想](piano-performance-simulator-spec.md)は背景資料として読む。初期MVPの限定範囲を、実装済みの機能へ適用し直さない。
3. Node.js 24系とnpmを用意する。直近の実行環境はWindows、Node.js 24.19.0。OS別のネイティブ機能や外部3Dモデルは不要だが、他OSの動作は未確認。
4. プロジェクトルートから次を実行する。インストールにはnpmレジストリへの接続が必要。

   ```sh
   cd apps/3d-motion-lab
   npm ci
   npm run check
   npm test
   npm run build
   npm run dev
   ```

5. ターミナルに表示されたURLをWebGLが使えるブラウザで開く。通常は`http://127.0.0.1:5173/`。このチャットで使っていた5174に揃えるなら`npm run dev -- --port 5174 --strictPort`を使う。**別環境では開発サーバーの起動が必要で、以前のlocalhost URLだけでは再開できない。**
6. 17のタイ・声部・休符・テンポ変化、16のレガートと押したままの指替え、15の保持中の掌移動・別鍵移動、14の保持音・部分離鍵、13の白黒音階と薬指↔親指、12の白黒和音・黒鍵5音、11の多音和音、10の混在譜面、08の両手音階、09の持ち替え、05の2音和音、06の移動比較、03の両端を確認する。全鍵表示と手元拡大、接触位置、指くぐり近似などの限界も確認してから改修する。

`evaluate`は互換用に既定値が`linear`、UIの初期選択は`scale`（区間ごとの動作計画）。`smooth`は従来の加減速方式。姿勢を比較・検証する際は必要な方式を明示する。和音計画・区間計画は音符配列をキーにメモリキャッシュされる。`performancePlanFor(notes)` が左右の音階区間を返す。`preparePerformance(notes)` は手首の動作量まで先に計算し、UIは読み込み中に呼んで再生開始後の初回計算を避ける。`heldPlansFor(notes)` は左右の保持区間を返す。任意の入力項目 `action: "substitute"` は同じ鍵を保持したまま別指へ渡す指定。通常の押鍵や同音反復と区別し、受け取り時刻・保持相手・長さを検証する。`FingerEvent.handoffFrom / handoffTo / opposed` と `HeldPath.crossings` は計画で生成する情報。軌道を持つ計画は `HeldPlan.path` の `times / positions / targets` に節点時刻・掌位置・eventsと同じ順序の音別接触点を保持する。`geometry` は固定方式の接触配置で、軌道方式の出入りはheldFrameの端点姿勢を使う。`HandFrame.depths` は `activeNotes / targets` と同じ順序の独立した押下率で、旧方式は省略して共通の `depth` を使う。描画は `keyDepth(frame,midiNote)` を使う。UIの音符配列は `$state.raw` で保持し、準備時と同じ配列を計画キャッシュへ渡す。現在の画面には音符編集機能がなく、入力を変更するときは新しい配列を検証して置き換える。

`evaluate`の第4引数は非演奏指の方式で、既定値`connected`。`reset`は前回の音階方式の基本姿勢への戻りを再現する。`scale`以外・音階方式の対応外区間ではこの引数は動作に影響しない。描画とUIの状態表示に同じ設定を渡す。

第5引数は打鍵方式で既定値`smooth`、前回の打鍵は`legacy`。音階計画は両方式をキャッシュし、同じ接触点・掌軌道で比較する。加減速打鍵の経路が届かない、または時間拡張で反対の手と同一鍵接触が生じる音階区間は`legacy`へ戻す。左右双方の加減速打鍵の接触時間を含めて保守的に判定する。フレームの`strikeStyle`と画面の「打鍵」に実際の適用方式を出す。`scale`以外・音階方式の対応外区間にはこの引数を適用しない。

第6引数は手首連動の有無で、API既定値`false`、UIは`true`を明示する。`wrist-motion.ts`が打鍵2方式×非演奏指2方式で共通の動作量を検証しキャッシュ。どの動作量も届かなければ手首を固定する。フレームの`wristMotion`で適用を示し、`forearmGuide`を`forearmEndpoints`の第3引数へ渡して描画する。`handPointLocal`は既存の手首軸の回転（Euler XYZ、Y=0）の逆変換。指の幾何解には元の親指対向量を引き継ぐ。

入力形式と再実行方法は [譜面JSONとタイの仕様](../../apps/3d-motion-lab/score-input.md) を参照。normalizePerformanceは入力を変更せず、明示したtie:start→continue…→stopを同じ手・声部・音程・指で結合。temposを積分し、音符・休符の両端を秒へ変換する。notes／sources／originsで元音符との対応を持つ。validateは正規化後に到達と接触を検証する。音符配列だけでは終端の休符を失うため、UIはinputLengthも参照する。
