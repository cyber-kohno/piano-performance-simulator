# ソロピアノ譜エディタ：ドメインモデルと検証方針

最終整理日：2026-10-29

この資料は、Scorehackを基準にしたソロピアノ譜エディタの目的、合意済みの設計判断、未決事項、段階的な開発方針を記録する。最終仕様を一度に固定するものではない。検証アプリで操作とモデルを確かめ、判断が必要になった段階でこの資料を更新する。

2026-10-27の方針変更：休符を含む記譜列を保存の正本とし、以前の「開始位置＋任意の数値音価」という保存構造を廃止した。カーソル単位（16分・8分・4分）での入力・移動と、明示的な音価編集・タイ追加を扱う。Shift＋F＋左右はこの保存構造を維持した便利操作として再導入し、操作対象のタイ列だけを再構成する。

現在は、この新方式の基盤を`apps/editor`で実装済み。休符込みの声部、音価からの位置導出、配置・削除、和音、明示的な音価編集、タイ列の移動・伸縮と既存の次小節への延長まで検証できる。操作対象は各小節・段のアクティブ声部（現在は最大3声部）。Shift＋Rで編集段を切り替える。OSMDによる前後3小節の楽譜プレビューも検証中。ファイル保存・読み込みとMusicXMLファイル入出力は未実装であり、本資料の「保存」は保存対象のモデルを指す。実装済みの範囲と今後の課題は第10〜12節で区別する。

## 1. 目的

作曲・編曲者が白紙からソロピアノ譜を入力・管理できるアプリを作る。主な価値は次の二つ。

1. ピアノロールを基準に、キーボードだけで音を速く入力でき、内部データは小節・声部・音価・タイなど楽譜として整合する。
2. ノートに割り当てた指番号を使い、将来3Dの手・指の動きで演奏をプレビューできる。

重みは譜面ドメインと入力体験がおよそ8割、3Dプレビューがおよそ2割。まず譜面モデルと編集の土台を検証する。初期版は完成品ではなく、理解が進んだ時点で作り直すことも前提とする。

主な用途は新規作成。MusicXMLの読み込みは将来対応したいが、アプリ内モデルで表現できる範囲をピアノ譜に限定するため、未対応要素や取り込み時の情報欠落を検出・説明する設計が必要になる。

## 2. Scorehackを基準にする範囲

Scorehackをゼロから置き換えるのではなく、既存のキーボード操作・ピアノロール・アウトラインの考え方を出発点にする。

### 引き継ぐ考え方

- OutlineとTimelineを切り替えるモード構成。
- マウスを使わず、キーボードだけで入力・移動・選択を完結させる。
- ピアノロール上の位置選択と、和音・ピッチのキーボード編集。
- 記譜上の音価を明示的に管理する。移動刻みは音符の種類と独立させる。
- カーソル、選択位置、アウトラインのフォーカスとスクロールを同期・自動追従させる。
- 拍子、テンポ、調号などの音楽上の基礎情報を扱う。
- 88鍵の音域を持つピアノロールを基本の入力画面とする。

Scorehackの既存操作や実装を必要に応じて参照する。特にキーリピート中のスクロール追従、ピッチ編集、フォーカス表示を参照する。音価の保存・編集方法は今回の記譜中心の方針を優先する。

### 引き継がない考え方

- ディグリーやコード進行を中心にした作曲モデル。
- 「伴奏」と「メロディ」を別トラック・別責務として分けるモデル。
- 歌詞入力。

コードを直接編集できることを中心にせず、音符と声部からピアノ譜を組み立てる。

## 3. データの基本構造

概念上の関係は次の通り。ペダルは初期段階では実装せず、関係も後で決める。

```text
Project
├─ Outline: ordered, parallel blocks
│  ├─ Initial values
│  ├─ Section marker
│  └─ Measure block
│     ├─ Upper staff
│     │  └─ Voices[]
│     │     └─ Elements[] (ordered notes / rests / full-measure rests / tuplet groups)
│     │        └─ Note: Pitches[] (each pitch may have fingering)
│     ├─ Lower staff
│     │  └─ Voices[]
│     │     └─ Elements[]
│     └─ Pedal (future; structure undecided)
└─ Position-based musical events (future; storage undecided)
```

Outlineの実データでは、初期値ブロック、セクションブロック、小節ブロックを一つの順序付き配列に並列で置く。小節配列をセクションの子としてネストしない。セクションはアウトライン上の境界・移動単位であり、後続する小節が直前のセクションに属することを表す。

小節は内部に上段・下段を持ち、それぞれ複数声部を持つ。声部はデータ構造そのものとして扱い、単なる譜面の見た目設定とはしない。ノートは一つの声部に属する。小節を削除すれば、その小節内に属する譜表・声部・ノートも削除される。

上下段を同じピアノロールで扱い、段と声部を切り替えて編集する。声部数は小節・段ごとに異なり、全小節共通のトラックにはしない。現在の作成上限は各段3声部とする。

### 声部の編集状態と小節境界（2026-10-28）

- アクティブ声部はカーソルのvoiceIndexとして管理し、プロジェクトへ保存しない。画面は第1〜第3声部、内部は0〜2で扱う。
- Qで現在小節・段に存在する声部を循環する。Shift＋Qは次インデックスがなければ全小節休符で作るだけで、選択を変えない。既存なら何もしない。第3声部からは追加しない。全小節への作成・自動補完はしない。
- 切り替え時はノート・範囲選択を解除する。フォーカス中ならそのノートの開始位置と選択ピッチを引き継ぎ、入力音価はカーソルの値を維持する。複数選択では操作端のノート開始位置と最高音を使う。
- カーソルが小節を跨ぐと、同じ声部がある場合だけ維持し、なければ第1声部へ戻す。段切り替え・OutlineからTimelineへ入る際も第1声部に戻す。
- 第2・第3声部を編集中、現在の段にその声部がない小節は黒のopacity:0.4で覆う。ブラインドは移動を妨げない。
- タイ追加・伸長・移動など小節を跨ぐ編集は、必要な各小節に同じ声部がある場合だけ許可する。なければ操作全体を拒否し、他声部へ振り替えない。範囲選択も別インデックスの声部へ跨がせない。
- 声部の削除は未実装。将来アウトライン側から保守する。

### ノートとピッチ

- 現段階で「ノート」と呼ぶ単位は、音符種類・付点とピッチ配列を持つ一つの記譜要素。
- 一つのノートは複数のピッチを持てる。したがって和音は同時開始・同一音価のピッチ配列で表現する。
- ノート内の全ピッチは開始位置・長さ・タイ構造を共有する。和音の一部の音だけ長さやタイを変える構造にはしない。独立した長さが必要な音は別ノートとして別声部に置く。
- 指番号はピッチごとに保持する。
- 「ノート」という名称が時間まとまりを指すのに適切かは、実装を進めてから再検討する。

### 位置と音価

各声部は音符・休符・全小節休符・連符グループの順序付き配列`elements`を持つ。通常の音符・休符は`value: { type, dots }`で表す。開始位置、数値の長さ、終了位置はノートに保存しない。各要素の開始位置は先頭から音価を累積して導出する。各声部の合計時間は小節の実長と常に一致する。

上下段・別声部間では、導出した時間区間が重なり、和音内に共通のMIDIピッチがある場合に衝突とする。段と声部IDで同じ声部を識別し、同じ段の別声部も別段と同じ規則で判定する。異なるピッチの同時発音と、終了・開始の境界が接するだけの場合は許可する。配置・移動・音価変更・伸縮・隣接生成・ピッチ変更・複数選択編集は確定前に変更対象全体を検証し、衝突時は操作全体を拒否する。この共通判定は実装済みで、編集UIは各小節・段のアクティブ声部を対象とする。

カーソルの位置はプロジェクトと別の一時的な編集状態であり、16分単位で保持する。`1`・`2`・`3`・`4`キーでカーソル単位を16分・8分・4分・32分に切り替え、その単位で移動・新規入力する。選択位置は単位切替で動かさず、既存ノートの音価も変更しない。配置範囲内の複数の休符は消費できるが、同声部の音符に重なる配置と小節末を越える配置は拒否する。

カーソル単位は`placementValue: { type, dots }`として一時的な編集状態にだけ保持する。ノート保存時もその音符種類・付点を使い、数値の長さは保存しない。ノート選択中の数字キーで既存ノートの音符種類、ドットで付点を明示編集する。F＋Aでカーソル音価の隣接タイ音符を追加する。Shift＋F＋左右では合計音価を一時的に数値計算し、音符種類・付点・タイ・休符へ書き戻す。

カーソル単位の四分音符は`.`で付点を付け外しできる。八分・十六分音符の単位では`.`は何もしない。付点四分音符の単位は移動・新規入力とも6ステップ分とする。数字キーは音符種類を選択し、同じ四分音符を再選択したときは付点を保持する。八分・十六分へ切り替えると付点を外す。ノート選択中は通常の`.`でノートの付点、Shift＋`.`でカーソルの付点を切り替える。複数選択中は通常の`.`では編集せず、Shift＋`.`で入力単位だけを変更する。

## 4. 拍子・小節・アウトライン

アウトラインの小節ブロックは実長を「実際の拍数／標準小節の拍数」と拍チップで表示する。通常の3/4は3/3、6/8は2/2、9/8は3/3、12/8は4/4とし、拍子記号と区別するため数値にBeatsを付ける。複合拍子では付点四分音符を1チップとし、短い小節は標準拍数の枠を残して実長に応じて埋める。保存上の小節長は音価の分数のまま維持し、表示用の拍数を導出する。

- 初期値ブロックはそのまま設ける。初期値の調は長調・短調でなく調号（五度圏の`fifths`）として扱う。
- 拍子は分子・分母を持つ。複合拍子では、操作・時間表示上の1拍を付点4分音符として扱う。
- 拍子と小節ブロックの実際の長さは別の値として持つ。
- 変拍子、弱起、終止の短い小節などのため、拍子の標準長と異なる長さの小節を許容する。例：4/4の曲の開始に1/4小節を置く。
- セクションは譜面上の必須記号ではなく、アウトライン上のまとまりとカーソル移動単位として保持する。
- 調号・拍子の変更は小節境界で扱う方針。テンポは調号・拍子のような小節単位ブロックと同じ扱いにせず、時間位置に置かれ、そこから有効になるイベントとして考える。
- テンポや将来の音部記号は「ノートに対して指定する」操作を想定するが、特定のノートに所有させるわけではない。内部保存形式やMusicXMLへの対応付けは実装時に決める。

小節ブロックのF＋左右で、実長を体感上の1拍ずつ増減できる。範囲は1拍から拍子の標準小節長まで。複合拍子では付点四分音符、3/8では八分音符を1拍とする。短縮後に音符が収まらない場合は、上下段・全声部を判定し、操作全体を拒否する。音符は切り詰めたり削除したりしない。休符は末尾の必要な範囲だけ調整し、全小節休符は新しい実長へ追従する。他小節の実長・小節内のノート位置・音価は保持し、全曲上の位置は小節列から再導出する。連続しなくなったタイは解除する。

## 5. 記譜上の音価・休符・タイ

音符の書き方をデータの正本とする。ノートの`value`に音符種類（`whole`・`half`・`quarter`・`eighth`・`16th`・`32nd`）と付点数を持たせ、衝突判定・表示幅・再生時間はそこから導出する。現在の入力単位は付点なしの16分・8分・4分・32分音符と付点4分音符、および4分・8分・16分音符の3連符とする。連符内の実時間は所属グループの比率も適用して導出する。

### 連符グループ（2026-10-29）

声部のelementsは通常の音符・休符・全小節休符に加え、連符グループを持つ。グループはactual／normalの比率、基準音符種類baseType、音符・休符の子配列を持つ。子の記譜音価の合計はactual個の基準音符分とし、実時間にはnormal／actualを掛ける。グループの保存位置・数値の長さは持たない。将来の5：4や、4分＋8分という混合音価のグループも表現できる。入れ子は今回扱わない。

初期入力は4分・8分・16分の3連符（3：2）。最小は16分音符の3連符、つまり8分音符の1/3。スラッシュで入力音価の通常／3連符を切り替える。記譜の種類を維持し、実際の刻みだけ2/3になる。32分での切り替えは行わない。入力の付点は外す。

最初の配置で3個分の連符グループを休符から確保し、1個だけ音符へ置き換える。同声部の全範囲が休符で、小節内に収まる場合だけ作れる。以後は同じ比率なら異なる音符種類も配置でき、必要な範囲の連続休符を消費する。大きな休符の途中にも配置でき、前後を休符で補完する。グループの基準音価・比率・全体の長さを保ち、既存音符との重なり・グループ末尾超過は拒否する。配置開始はグループ内の記譜16分刻みとし、最小の16分3連符より細かい休符を新たに作らない。削除で同音価の連符休符へ戻し、空でもグループを保持する。位置・時間は分数で導出し、UI向け数値への変換は境界に留める。MusicXMLのdivisionsは表示範囲の時間分母の最小公倍数から選び、time-modificationと連符の開始・終了を出力する。

今回の対応は入力・移動・選択・和音／音程編集・削除・隣接生成・タイ追加・プレビューまで。連符内の音価変更、移動、伸縮、正規化、グループ解除・グループ自体の小節またぎは未対応として拒否する。既存の通常音符の編集でも連符を破壊する場合は拒否する。詳細はEditor READMEを参照する。

### 休符を含む声部

- 小節追加時は、上下段それぞれのvoice 0を全小節休符で埋める。
- 全小節休符`kind: 'measure-rest'`は通常の全休符と区別し、時間はその小節の実長から求める。弱起・3/4・6/8にも同じ方式を使う。
- 通常の休符は`kind: 'rest'`と`value`で保持する。
- ピアノロールでは休符を描画しないが、保存対象として必ず保持する。
- 要素の位置は、声部内の先行要素の音価を合算して求める。
- どの編集でも、声部内の合計時間を小節の実長に一致させる。

例えば、4/4の小節頭から16分一つ進んで入力すると、16分休符→16分音符→8分休符→4分休符→2分休符となる。

### 編集時の休符調整

| 操作 | 内部の変更 |
|---|---|
| 配置 | 範囲内の休符を前後の休符とカーソル単位の音符へ置換 |
| 削除 | 同じ音価の休符へ置換。後続要素の位置を維持 |
| 音価拡大 | 直後の休符を消費。同声部の他ノートへの衝突は拒否 |
| 音価縮小 | 空いた時間に休符を補完 |
| 将来の休符整形 | 合計時間を保って休符を分割・結合 |

新しく生じた休符範囲や、入力で影響を受けた休符だけを自動整形する。無関係な既存休符を毎回一括で再正規化しない。将来「16分休符2個」と「8分休符1個」をユーザーが選んだ場合、その並びを保持できることが目的。

### 音符とタイの明示編集

- ノート非選択中の数字キーは入力単位を変更する。選択中は1/2/3/4でノートの音符種類を変更し、Shift＋1/2/3/4で入力単位を変更する。ドットで付点なし／付点一つを切り替える。数字キーで音符種類を変更すると付点を外す。同じ種類を再選択した場合は付点を維持する。
- フォーカス中は`Note 1/4 · Input 1/16`のように両方を表示し、Note側の文字色を淡い暖色にする。
- F＋Aで直後へカーソル音価のノートを作り、同じ和音・指番号を複製してタイ接続する。新しいノートへフォーカスを移し、対応するピッチ選択と入力単位を保持する。以前のShift＋音価数字キー案をこの操作に置き換える。
- 既に後続タイがあるノートでは追加を拒否し、列末尾から延長する。小節末では既存の次小節へつなげられるが、追加音符自体の小節またぎ、衝突、曲末超過は拒否する。小節を自動追加せず、指定音符の記譜を自動で結合・分割しない。
- 16分位置から4分音符を置くなど、開始位置と音符種類を独立させる。拍境界で音符を勝手に分割・結合しない。
- ノート選択中の数字キーなど単独の音価変更が小節末を越える場合は拒否する。明示編集ではF＋Aで次小節につなぐ。Shift＋F＋左右の便利操作は下記の自動分割規則を使う。
- タイ列途中の音符種類を変える場合は、後続のタイ接続ノートを動かして連続性を保ち、空白の休符も調整する。無関係な音符を押し出さない。
- タイ列も通常の選択は個々のノート。ピッチ追加・変更は列全体に連動する。`tieFrom`・`tieTo`のIDで接続し、音価変更時の後続移動に対応する。
- Dホールド＋左右でタイ列全体を入力単位ずつ移動する。選択中のノートID・ピッチ選択・音符種類・付点・指番号を保持する。元の範囲は休符で補完し、移動先の休符を消費する。衝突はScorehackと同じく移動先で判定する。
- 曲の範囲外、移動先の同声部ノートとの重なり、音符単体が小節境界をまたぐ移動は拒否する。各音符が収まる場合は既存小節間で移せる。自動分割・小節の自動追加は行わない。
- 手動の接続解除、列全体の明示選択ショートカットは後で追加する。

付点16分は使用でき、付点32分は禁止する。通常音価の基準は16分＝1、32分＝0.5で、通常音価の休符・伸縮・正規化は32分刻みに対応する。連符の位置・時間・衝突判定には分数を用い、既存UIとの境界でのみ数値へ変換する。グリッド線は16分間隔を維持する。連符は前述の比率とグループ構造で保持する。

操作ごとの対象と小節境界の扱いは次の通り。いずれも小節を自動追加しない。

| 操作 | 対象 | 小節境界・記譜の扱い |
|---|---|---|
| A | 新しい独立ノート | 入力音価で配置。単体の小節またぎは拒否 |
| 数字／ドット | 選択ノートと、位置を追従する後続タイ音符 | 明示した音価を維持。各音符の小節またぎは拒否 |
| F＋A | 選択ノートの直後に新しいタイ音符 | 小節末から既存の次小節へ接続可。追加音符自体は一小節に収める |
| D＋左右 | タイ列全体 | 各音符の記譜を維持して移動。各音符の小節またぎは拒否 |
| F＋左右 | 選択音符と、位置を追従する後続タイ音符 | 単一音符で表せる次の音価へ変更。各音符の小節またぎは拒否 |
| F＋Enter | タイ列全体 | 開始位置・合計音価を維持して正規化。元の選択開始位置を含む音符へフォーカス |
| Shift＋F＋左右 | タイ列全体 | 開始位置・拍子に沿って再整形。必要範囲が休符なら既存の次小節へ自動分割・タイ接続 |

### 単体伸縮・手動正規化・タイ列の伸縮

- F＋左右は選択音符だけの音価を変更し、フォーカスを維持する。入力単位ずつ候補を探索し、単一音符で表現可能な最初の長さを採用する。候補は32分・16分・付点16分・8分・付点8分・4分・付点4分・2分・付点2分・全音符。候補がなければ何もしない。自動分割・結合は行わない。
- 後続タイ音符は元の音価を保ったまま追従させる。選択音符と後続のいずれかが小節をまたぐ場合、または衝突する場合は変更全体を拒否する。
- F＋Enterは選択音符を含むタイ列全体を、開始位置・合計音価を変えずに下記規則で正規化する。指番号の変化点も保持する。フォーカスは操作前の選択音符の開始位置を含む結果音符へ引き継ぐ。単独音符も対象とし、キーリピートでは実行しない。
- 複数選択中はこれらの音価編集・正規化を行わない。

#### Shift＋F＋左右による伸縮と自動整形

- 明示編集に併設する便利操作。保存モデルに自由な数値の長さを戻さない。
- 通常の選択は個々の音符のまま、Shift＋F＋左右は接続された列全体の合計音価を入力単位ずつ加減する。
- 列の開始位置を固定し、結果の末尾ノートへフォーカスする。和音・ピッチ選択・入力単位を維持する。
- 操作対象の列だけを再構成する。合計音価だけでなく小節内の開始位置と拍子を考慮し、拍の分割位置を見せることを優先する。音符の基本単位に位置を合わせ、拍の途中から始まる音は次の拍の境界で分割する。複合拍子は付点4分のまとまりとその中の位置を基準にする。
- この条件と小節境界・指番号の変化を残した区間内で、単付点までの音価を使って個数を最小化する。同数なら付点のない先頭音符を優先する。小節頭からなら5ステップ＝4分＋16分、6＝付点4分、7＝4分＋付点8分。
- 4/4で小節頭から16分一つ後に開始する場合、合計1〜4ステップは「16分」「16分＋16分」「16分＋8分」「16分＋8分＋16分」とする。先頭の16分を残し、後続側をまとめる。
- 位置は記譜列から導出する。短い小節が先行していても、全曲位置でなく各小節内の位置で判定する。ノート選択中の数字キーによる明示指定では16分裏の4分音符なども引き続き許容し、この既定整形を保存モデルの制約にしない。
- Shift＋F＋右で小節末を越える場合、既存の次小節の必要な範囲が休符なら、境界で音符を分割してタイ接続する。複数の既存小節も同様に扱う。次小節全体が空白である必要はないが、伸長範囲内に同声部の他ノートがあれば操作全体を拒否する。
- 曲末を越える伸長は拒否し、小節を自動追加しない。短縮では不要な後続ノートを休符に戻す。F＋Aによる明示的な追加も維持する。
- 長さ0以下、他ノートとの衝突は拒否する。休符は必要な範囲だけ調整し、範囲外の手動整形を保持する。
- ノート選択中の数字キー・ドット・F＋Aを使う通常の明示編集では、この自動正規化を行わない。

## 6. 調号・実音・譜面上の音名

初期値テンポは、初期値ブロックにフォーカス中のF＋左右で1ずつ変更できる。左で減少・右で増加し、10〜400の範囲で停止する。Fホールド中はTempo行全体を強調する。

初期値拍子は、小節ブロックが一つもない場合に限り、初期値ブロックのD＋方向キーで変更できる。上下で4分系／8分系、左右で2/4・3/4・4/4または3/8・6/8・9/8・12/8を選択し、各列の端で停止する。上下の対応は2/4↔6/8、3/4↔9/8、4/4↔12/8とし、3/8から上は3/4へ戻す。Dホールド中はMeter行全体を強調する。小節ブロックが一つでも存在すれば全方向の変更を拒否する。

初期値ブロックにフォーカス中、C＋左右で異名同音を同列に含む調号候補を選択できる。長調名で示した右方向の順序はC → G → D → A → E → B → C♭ → F♯ → G♭ → C♯ → D♭ → A♭ → E♭ → B♭ → F → Cで、左は逆順となる。両方向とも循環し、異名同音用の上下選択は設けない。保存値は`fifths`とし、既存の実音は保持する。Cホールド中は初期値のKey行全体を強調する。

- 調号変更後も、既存ノートの実際に鳴る音は維持する。
- 調号を変えた結果、譜面上の音名・臨時記号は調号に沿うように再表記したい。例えばF majorからC majorへ変えたとき、元からB♭として鳴っていた音は実音を保ったままフラット表記になる想定。
- 調号に照らして不自然な異名同音表記（例：F majorの文脈でA♯と保持する）を許すべきではない。
- したがって、実音高（現在の実装ではMIDI pitch）と譜面上の音名・臨時記号をどう導出・保持するかを分けて設計する必要がある。
- 「音名を完全に自動算出するか」「ユーザー指定の綴りを保持するか」「調号変更時に明示的な再表記を行うか」、臨時記号の小節内適用規則や異名同音の例外は未決事項。ディグリーを入力モデルに持ち込まない。

## 7. MusicXMLの位置づけ

MusicXML互換は単なる他アプリとの連携要件ではなく、譜面データとして整合したドメインモデルを設計するための基準である。ミリ秒だけのノート、声部のない音の羅列など、楽譜として不十分な独自モデルにしない。

- 主目的は内部データの音楽的・記譜的な整合性を保つこと。
- MusicXML出力後にMuseScoreで開いたとき、ノート・小節・声部・タイ・調号などのレイアウトが壊滅的にならないことを妥当性の確認に使う。
- MuseScoreとの完全な往復互換、強弱・アーティキュレーション・スラー・ペダル・ページレイアウト等の全要素保持は当面の要件ではない。
- MusicXML読み込みは将来対応。アプリ内で表現できない要素は、黙って不正確に読み込むのではなく、取り込み前後に非対応・欠落を把握できる仕組みが必要。
- MusicXMLの詳細な要素対応表、インポート時の制約、譜面の見た目の調整方法は、譜面出力に進む段階で仕様化する。
- 保存上の声部は休符込みの順序付き記譜列とし、出力時に数値の`duration`を音符種類・付点から算出する。MusicXMLは休符も`note`の一種として扱い、全小節休符には`rest measure="yes"`を使う。内部のピッチ配列・上下段別の声部構造は維持し、XMLの並びに対応付ける。

## 8. ペダル・運指・3Dプレビュー

### ペダル

ペダルは初期段階では扱わない。MusicXML上のペダル表現を調べた上で、独立したペダルレイヤーにするか、下段のノートと関連付けるかを後で決定する。

### 運指

ピッチごとの指番号1〜5はモデルに実装済みで、タイ追加・編集時に保持する。指番号を入力するUIは未実装。運指の自動割当、両手間の整合、交差・持ち替え等のルールは別途設計する。まずは譜面側の指定を3Dプレビューへ渡せることを優先する。

### 3Dプレビュー

プレビューは譜面ドメインが主、3D表示が従の位置づけ。記譜列とテンポから開始時刻・演奏時間を導出し、ピッチ・手・指番号とともに3D側へ渡せる境界を設計する。上下段と左右の手を同一視する規則は未決定。演奏動作の補間や手の運動学は[3D Motion Lab側](../3d-motion-lab/general-motion-engine-plan.md)で別途検証する。そちらの秒／拍JSONは動作検証用の入力形式であり、エディタの保存モデルではない。接続用の変換処理は未実装。

## 9. UIと入力の初期方針

- レイアウトはScorehackを基準にし、左をOutline、残りをTimelineのメイン領域にする。
- Timelineは時間軸ヘッダ、ピッチ一覧、ピアノロールで構成する。時間軸ヘッダの横位置、ピッチ一覧の縦位置はピアノロールと同期し、それぞれの他方の軸は固定する。
- 上段・下段は同じピアノロールを使い、Shift＋Rで編集段を切り替える。非編集段は半分の高さ・暗い青／赤・透明度0.8で表示する。
- 現在は上下段それぞれで最大3声部を切り替えて編集できる。段切り替え時は位置と入力単位を維持し、ノート非選択・第1声部に戻す。ノート選択中はその開始位置（範囲選択では操作端のノート）を使い、ピッチは上段C4／下段C3へ初期化する。OutlineからTimelineへ入る際は従来どおり上段・小節頭・非選択・四分音符・C4に戻す。
- アプリ内の正式な表示文言は英語で統一する。検証用の開発メモは日本語可。
- マウスを使わず操作を完結させる。スクロールバーは見せず、カーソル移動に合わせて必要な領域を自動スクロールする。
- Scorehackと同様、画面幅に応じたレスポンシブ再配置は行わず、最低フレームサイズを基準にする。Tauri導入時に最小サイズを設定する。
- 初期版は新規プロジェクトの検証画面から始め、エントリー画面やファイル選択は設けない。

## 10. 現在の検証アプリ

実装先は`apps/editor`。Svelte 5 + TypeScript + Viteで進め、Tauriへの移行は本格開発時に検討する。

現時点のプロトタイプには、初期値・セクション・小節を持つOutline、上下段と複数声部を含むプロジェクトモデル、上下段のアクティブ声部へのカーソル単位による音符入力、Timelineのフォーカス、88鍵ピッチ表示がある。声部は休符込みで小節を埋め、キー入力で休符の一部を音符へ置き換える。配置・削除、ピッチ編集、和音入力、ピッチ単位選択、調性に応じたノート色、列フォーカス、自動スクロールを検証できる。

数値の長さを保存する旧方式は撤去した。ノート選択中の数字キーによる音符種類変更、ドットの付点編集、F＋Aの明示的なタイ追加、D＋左右のノート移動、Shift＋F＋左右による範囲限定の伸縮・再構成は実装済み。休符表示・手動整形、声部削除、MusicXML入出力、ペダル、運指入力、3D連携は後の段階で扱う。

## 12. 段階的な進め方

一度に全仕様・全機能を作らない。各段階で操作感とドメインの妥当性を確認し、次の段階へ進む。

検証アプリで基盤実装済み：

1. Outline・Timelineのレイアウト、モード切替、キーボードフォーカス。
2. 初期値の読み取り専用表示、セクション・小節の追加／削除、カーソル同期と自動スクロール。
3. 休符を含む記譜列と、カーソル単位による入力・削除・和音編集。
4. 音符種類・付点の明示編集、隣接するタイ音符の追加、タイ列全体の移動。
5. 開始位置・拍子を考慮したタイ列の伸縮と、既存小節への分割・接続。

今後、必要な段階で仕様を詰める項目：

1. 声部削除などの保守操作。上下段の切り替えと各小節・段の最大3声部の追加・切り替え・編集は実装済み。
2. 休符の表示・手動整形、調号と音名表記、拍子・小節長・位置イベントの編集。
3. 初期プレビューの描画範囲・レイアウトを検証し、MusicXMLファイル出力とMuseScoreでの記譜の妥当性確認へ進む。
4. 指番号の入力と3Dプレビューへの連携。
5. ファイル保存・読み込み、MusicXML取り込み時の非対応要素の検出・説明。

各段階は直線的な必須順序ではないが、譜面ドメインの判断を3D表示やファイル連携より先に固める。
