# 段階的な保守向け移行計画

作成日：2026-11-03

## 進め方

操作仕様と保存モデルを維持し、各段階で既存テスト・型チェック・ビルドを通す。キー操作に関わる段階ではブラウザーでも主要な操作を確認する。新機能追加と構造変更を混ぜない。namespace＋default exportは移行する責務から適用する。

## 段階と確認地点

1. 編集actionと共通更新境界
   - ノート・アウトライン・ペダルの変更をaction/editorへ集約する。
   - トリル・テンポ・音部記号・スラーの整合処理と正規化時の参照更新をAppから移す。
   - 設定モーダルは複数項目を1回の編集として反映する。
   - 確認：既存テスト、UIなしのactionテスト、追加・削除・タイ・正規化・モーダル・ペダルのキー操作。
2. 音楽規則・譜面構造と参照処理
   - model/stateに混在する純粋な音楽規則をdomain/theoryへ、譜面の型・制約・参照をdomain/scoreへ移す。
   - カーソル・選択から独立した譜面編集関数へ分解する。段階1のactionを公開窓口として維持する。
   - 確認：拍子・調号・連符・タイ・複数声部を含むテストと編集操作。
3. UI・外部描画の境界
   - OSMD/MusicXML関連をinfraへ分け、キーバインド・下書き・表示状態をUI側へ整理する。
   - スクロールや表示を変えず、Appは組み立てに近づける。
   - 確認：追従スクロール、選択表示、前後小節プレビュー、各モード。
4. Tauri最小構成と起動準備
   - Scorehackを参照し、SoundFontの読み込み・初期化をinfra/audioとservice/startupへ実装する。
   - 確認：正常起動・ファイル不在・読み込み失敗・再試行・終了時解放。
5. 演奏イベントと基本再生
   - domain/performanceで通常音符・タイ・テンポをイベントへ変換する。
   - service/playbackで再生・停止を管理する。
   - 確認：時刻の自動テストと実音確認。続いてペダル・各演奏表現へ広げる。

段階1完了後、段階2は2a（音楽規則・保存モデル・位置参照）、2b（残る表現モデル・演奏解釈の配置整理）、2c（カーソル依存の編集アルゴリズムの分解）に分けて進める。各区切りで動作を維持する。Tauri移行・再生はこの構造変更と同時に実装しない。
